# 章级回报决策边界

## 职责

本模块拥有回报决策的证据校验与新鲜度判断。规划 AI 使用已注册的 `planner.chapter.plan` 返回决定；本模块不能按账本状态自行创造压力、兑现或延期动作。

候选来自当前 canonical snapshot，最多五项，去重后逐项决定。决定必须引用当前章合同原文；延期、到期但仍只施压、部分兑现均须引用提供的未来章节安排。部分兑现还要列出剩余义务。引用校验是必要的机械校验，不代表已经独立证明推理语义成立，文学质量仍由审查与阅读验收承担。

## 依赖与持久化

- `PlannerService` 组装当前合同、已写证据、未来规划并调用规划 Prompt，然后使用本模块校验。
- 精确引用来源由 `context.ts` 单独生成必选、不可摘要的 `payoff_planning_evidence` 块；不能把当前合同或未来引文只藏在可压缩的状态快照中。未来安排仅投影实际提供的章节序号、标题与摘要，输入与校验使用同一份数据。

- 决策随 `StoryPlan.rawPlanJson` 保存，附决策版本、执行合同摘要及前文证据摘要；无需数据库迁移。
- `GenerationContextAssembler` 只读取匹配当前合同和前文的决定，交给 `ContextAssemblyService` 投影为写作指令。
- 账本包含保密文字不构成取消整个回报的理由。投影保留 AI 的动作与范围，独立保留章级保护信息。
- 已写章节不因旧计划缺少决策而自动重建；未写章节的旧计划需重新规划。

## 失败与恢复

缺少候选决定、引用错误或虚构延期落点不能默认为继续施压。`requires_replan` 抛出带明确中文原因的 `PayoffPlanningReplanRequiredError`，调用方不能把它降级为空决定后继续写。

证据校验必须在正式规划 Prompt 的 `postValidate` 内执行，让拼接引文、改写标点、漏候选等模型错误进入既有的一次语义重试。保存前仍执行同一校验，不能仅依赖模型自报通过。已校验的 `requires_replan` 是有效业务决定：Prompt 层允许它返回，服务层再抛明确重排错误，不消耗纠错轮次强迫模型改判。

该错误目前没有新增专属导演修复面板或独立的持久化恢复阶段。它沿现有调用方错误路径返回，仍需从源工作区修订未写章节规划。不能宣称该模块已实现自动重排未来节奏板，也不能借此把已完成正文的局部质量债改成全局失败。
