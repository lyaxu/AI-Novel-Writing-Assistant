# 验收输入、证据投影与缓存身份

本模块拥有验收调用与缓存的统一输入、场景因果证据到现有问题的确定性投影，以及验收复用身份；不拥有正文写入、AI语义判断或重试预算。

`expectedSceneKeys` 只来自已保存且登记了因果合同的场景。新审查必须精确覆盖；旧资产没有该合同则使用空范围，不伪造已完成审查。失败的因果结论映射到局部问题和风险，未知证据不产生编造补文的指令。完整证据由上层接收服务保存到审查元数据。

调用与缓存还共用输出预算：基础4224，每个需审场景预留1536，按最多8场封顶16512；三场为8832。额度同时容纳原场景判断与关键行动状态链，模型路由可根据供应商和思考配置调整实际额度。这里仅提高本次调用证据输出的上限，不新增调用，也不承诺固定实耗或模型质量。

## 关键行动状态边界

新验收每场选择一个决定结果的关键行动，以 `actionStateChecks` 表达行动前状态、行动需要的条件、行动后状态和状态过渡；只检查相关的身体、物品、能力、知识、位置维度，通常一至两项。没有旧场景合同的章节使用 `chapter` 范围。旧持久化报告可缺少该字段，不能把旧报告解读为已经做过行动核验；新 Prompt 版本及有效输入进入缓存身份。

`current_prose` 的 sourceId 是本章 ID，`established_context` 的 sourceId 只能是 `writtenEvidence.chapters` 中已写前章 ID。引文按实际正文核对并检查前状态与行动的顺序；计划、摘要、规划者的来源声明不能认证事实。支持先解穴后站立、已建立的隔空术法等合法过渡，不以写实常识替代小说世界规则。规则与文本间的语义关系仍由同一次 AI 审查判断，工程校验不声称理解剧情。

Prompt 的证据校验只消费结构化结果：错误来源或缺失引用降为 `insufficient_evidence`，明确的状态冲突与过晚的前置建立不能保持 `earned`；这些降级不触发新的格式修复/语义模型调用。服务将确证问题映射为优先的局部连续性修复，未知来源映射为可见质量债且不给编造补文指令。场景结果虽出现，只要其关键行动不成立就不能维持场景 `earned`。完整动作检查和覆盖缺口写入 AuditReport 元数据，高总分不能覆盖它们。

此模块不改变完成优先策略、既有修复预算或人工恢复要求，不制造新的全局停写原因。局部问题在现有修复与质量债路径处理。测试覆盖的是给定结构化判断的校验、消费和兼容，不证明模型总能识别真实小说中的问题。

身份使用 Prompt Registry 中的验收资产版本、经过上下文选择和槽位/高级模板覆盖的消息，以及解析后的模型配置。只持久化摘要，不保存 API Key 或完整提示词；外围运行包的生成时间不进入身份。

调用方通过 `index.ts` 使用能力。`ChapterAcceptanceAssessmentService` 提供身份查询，`ChapterQualityGateService` 负责内存复用、同实例在途合并及持久缓存。身份不可确认时跳过缓存而非复用历史结果。模型执行后再次检查身份，配置变化时不发布该次缓存。

身份准备复用现有提示词和模型解析 API，不发起模型请求。验收执行输入或 Prompt Runner 的覆盖规则变化时，必须同步检查这里的身份准备逻辑与隔离测试。当前同实例合并不承诺跨 Worker 的排他执行；持久领取与恢复在后续预算阶段单独验证。
