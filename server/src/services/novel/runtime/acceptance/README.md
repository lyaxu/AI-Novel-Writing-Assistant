# 验收输入、证据投影与缓存身份

本模块拥有验收调用与缓存的统一输入、场景因果证据到现有问题的确定性投影，以及验收复用身份；不拥有正文写入、AI语义判断或重试预算。

## 问题保留与修复预算

规范化验收必须完整保留模型判断及动作、因果、推进投影形成的问题、修复指令和未兑现义务。投影可能在原问题前增加条目，不能按数组前几项截断，否则低确定性的派生风险会挤掉已识别的严重重复或连续性问题。修复上下文同样不得按条目数量静默丢弃问题。

运行时报告和持久报告的元数据保留完整问题（含结构化来源证据）、指令、义务及修复可行性结论，供修复和后续诊断核对。一次执行的补丁数量与自动重试次数属于执行预算，不是问题记录上限；预算内未处理的问题必须继续可见，不能被解释为问题已消失。

来源校验耗尽后，`sourceValidationIssues` 标记的问题保留在报告及元数据中，其原始严重度和修复建议可追溯，但不得转换为改稿命令。`actionableIssues` 统一过滤运行包修复上下文、自动流水线、补丁问题目录及手动审计选择；报告展示为待核验风险，原始断言保留在元数据。`deferredRepairDirectives` 与 `deferredMissingObligations` 仅作审查记录。若全部问题来源未核实，应停止本次修文并保留正文，不能用空列表触发的通用润色任务替代。

`expectedSceneKeys` 只来自已保存且登记了因果合同的场景。新审查必须精确覆盖；旧资产没有该合同则使用空范围，不伪造已完成审查。失败的因果结论映射到局部问题和风险，未知证据不产生编造补文的指令。完整证据由上层接收服务保存到审查元数据。

调用与缓存还共用输出预算：基础5760（含固定三维推进证据的1536额度），每个需审场景预留1536，按最多8场封顶18048；三场为10368。额度同时容纳原场景判断、关键行动状态链及跨章推进检查，模型路由可根据供应商和思考配置调整实际额度。这里仅提高本次调用证据输出的上限，不新增调用，也不承诺固定实耗或模型质量。

## 关键行动状态边界

新验收每场选择一个决定结果的关键行动，以 `actionStateChecks` 表达行动前状态、行动需要的条件、行动后状态和状态过渡；只检查相关的身体、物品、能力、知识、位置维度，通常一至两项。没有旧场景合同的章节使用 `chapter` 范围。旧持久化报告可缺少该字段，不能把旧报告解读为已经做过行动核验；新 Prompt 版本及有效输入进入缓存身份。

`current_prose` 的 sourceId 是本章 ID，`established_context` 的 sourceId 只能是 `writtenEvidence.chapters` 中已写前章 ID。引文按实际正文核对并检查前状态与行动的顺序；计划、摘要、规划者的来源声明不能认证事实。支持先解穴后站立、已建立的隔空术法等合法过渡，不以写实常识替代小说世界规则。规则与文本间的语义关系仍由同一次 AI 审查判断，工程校验不声称理解剧情。

Prompt 的证据校验只消费结构化结果：错误来源或缺失引用降为 `insufficient_evidence`，明确的状态冲突与过晚的前置建立不能保持 `earned`；这些降级不触发新的格式修复/语义模型调用。服务将确证问题映射为优先的局部连续性修复，未知来源映射为可见质量债且不给编造补文指令。场景结果虽出现，只要其关键行动不成立就不能维持场景 `earned`。完整动作检查和覆盖缺口写入 AuditReport 元数据，高总分不能覆盖它们。

此模块不改变完成优先策略、既有修复预算或人工恢复要求，不制造新的全局停写原因。局部问题在现有修复与质量债路径处理。测试覆盖的是给定结构化判断的校验、消费和兼容，不证明模型总能识别真实小说中的问题。

## 前后章实际推进边界

`progressionChecks` 每次覆盖 `event_repetition`、`knowledge_repetition`、`prior_goal_followthrough` 三维，分别核验事件职责、认识增量和前章行动决定的承接。AI 对实际前后正文判断 `progressed`、`justified_repetition`、`stalled`、`insufficient_evidence` 或 `not_applicable`；工程只验证准确原文来源和字段覆盖，不能从词频、场景名或章数推断剧情重复。

`progressionProjection` 把已核实来源的 `stalled` 映射到既有 plot 局部修复，证据不足只记录质量债，不指令补造前情。局部修复须保留细腻与慢热中的有效认识、关系和情绪变化，不要求每章完成目标、离开地点、战斗、成功或反转。再次尝试若带来新阻力、证伪、代价、关系后果或主动改选，仍可成立。旧报告可缺字段；新调用必须给三维结果，完整结果存入 AuditReport 元数据，缓存身份随 Prompt 版本变化。

`rolling_window_review` 现有运行时投影不是独立的多章语义模型审查。本模块借已有接收调用中的 `written_evidence` 做前后对照，不因此增加滚动模型调用。首章无继承目标不是停滞；后章无可读前文必须承认无法核验，不能声称前章不存在目标。结构化判断通过及单元测试通过均不能替代真实全文审读。

身份使用 Prompt Registry 中的验收资产版本、经过上下文选择和槽位/高级模板覆盖的消息，以及解析后的模型配置。只持久化摘要，不保存 API Key 或完整提示词；外围运行包的生成时间不进入身份。

缓存命中必须同时满足正文哈希、完整请求身份以及当前三维检查的完整后校验形状。不得在身份不匹配时按相同正文寻找最近成功报告：即使正文不变，Prompt 版本、前文证据、模型或覆盖模板变化仍要求重新验收。旧报告保留历史读取兼容，但不能冒充新版本已经完成的审查；没有三维结果的新响应也不写入成功缓存。此边界只约束复用，不自动发起额外重试。

调用方通过 `index.ts` 使用能力。`ChapterAcceptanceAssessmentService` 提供身份查询，`ChapterQualityGateService` 负责内存复用、同实例在途合并及持久缓存。身份不可确认时跳过缓存而非复用历史结果。模型执行后再次检查身份，配置变化时不发布该次缓存。

身份准备复用现有提示词和模型解析 API，不发起模型请求。验收执行输入或 Prompt Runner 的覆盖规则变化时，必须同步检查这里的身份准备逻辑与隔离测试。当前同实例合并不承诺跨 Worker 的排他执行；持久领取与恢复在后续预算阶段单独验证。
