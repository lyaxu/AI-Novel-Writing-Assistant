# 建议的独立语义核验

第一轮建议是草稿，不是授权依据。第二轮模型独立读取同一权威上下文，主动寻找当前候选执行安排中的反证，并直接返回纠正后的最终建议及逐项核验结果。纠正建议不是修复候选，也不能替代原有章节与窗口审查；不设置自动第三次调用。

`contract.ts` 持有核验输出合同，`index.ts` 为服务消费的唯一入口。Prompt 归属 Prompt Registry。此模块不读取数据库、不调用模型、不保存授权；调用编排、来源新鲜度与核验回执由 AdviceService 负责。

`checks` 与最终 `advice.options` 一一对应，而非与原草稿绑定。`corrected` 可表示修正措辞后仍为仅复核，但必须重新满足版本、精确引文、审查争议及完整闭合合同；它不能作为绕过依据检查的状态。

模型判断引文是否支持结论以及是否存在未解决矛盾。确定性校验只检查合同、候选执行字段的真实路径和原文、方案章节归属，以及结构化反证与执行方向的一致性。真实引文也可能被错误解释，因此仅复核方向一旦存在模型标记的反证便拒收；应由独立模型纠正为先修复再复核，而非程序通过关键词替它作创作判断。

`blocked` 只能形成需返回来源工作区处理的方案，可作为所有方案均不可直接执行时的推荐，但不能成为恢复授权。既有引用守卫与来源指纹仍需执行，核验结果本身不证明候选已改动。

非 blocked 方案必须为涉及的每个章节提供至少一处当前候选原文。缺少候选资料时，blocked 可返回空证据，不能为了填满数组编造来源。

跨来源矛盾允许附加 `chapterEvidence[i].content` 的连续正文引文；它必须来自实际提供的正文，不能使用摘要、历史判断、错误数组位置或近似匹配。正文证据不计入候选章节覆盖，不能用前章原文代替本章执行合同。当前候选出处和已写事实出处是两类权限，不能因核验对象是候选就禁止引用已写事实。

## 独立核验的单一版本输入

两轮都使用白名单上下文，不携带基线规划、同步规划、历史模型执行稿及旧指导，避免同字段多个版本混入。保留当前候选、后续只读路线、正文、原选意图、书级约束，以及明确标注为待验证主张的当前审查；不提供历史账本中的旧原句。第一轮草稿仍不可信。

模型仅以 `evidenceId` 选择本次目录证据。目录从当前执行字段、正文连续片段和只读后续计划构造；标识绑定精确来源路径与内容。服务通过 `resolveAdviceSemanticReview` 恢复路径与引文，再执行既有守卫，不接受模型自行改写引文。旧路径引文格式仅用于已解析结果及保存回执，不是新模型的输出合同。目录选择解决版本和原文归属，语义关系仍由独立模型判断，不能把真实 B 引文解释成仍要求 A。


当前审查问题进入系统生成的 `issueCatalog`，含稳定目录标识及所属章节，业务问题 ID 缺失时仍可定位。模型先逐项返回 `issueAssessments`，再给最终方案：present 必须修复或来源处理，insufficient 不能仅复核；其他状态不等于整窗自动通过。解析器校验完整不重复覆盖及证据来源，不猜测问题真假。解析后的评估与精确证据可作为回执保存；第二轮拒收保留该轮原始响应，不能误保存第一轮草稿代替失败证据。


模型线格式保持单层根结构：`issueAssessments`、`checks`、`summary`、`recommendedOptionId`、`options`。不把最终建议包装到 `advice` 对象中，减少长输出尾部把检查数组错嵌进去的风险。解析器仍复用共享建议合同的字段与跨字段校验，再组装为既有内部 `{advice, checks, issueAssessments}` 结构；存储格式及老结果校验不因线格式调整而放宽。


问题目录同时覆盖 `quality.chapters[*].issues` 与 `quality.window.issues`。窗口条目使用明确的 `scope=window` 和完整授权章节 `affectedChapterIds`；兼容 `chapterId` 仅定位首章，不能缩小窗口职责。可执行备选互斥而非接力，每项必须独立处理所有仍存在或资料不足的章节/窗口问题；不同备选的范围不能合并计算覆盖。返回来源工作区且不可直接执行的方向可诚实说明其处理范围。
