# 规划修复建议边界

此模块把暂停中的规划证据转为供新手选择的方向，不批准规划，也不执行修改。HTTP 显式 POST 预约一次建议生成；GET 只读，重启后遗留的运行记录显示不确定，必须用新请求标识明确重试。

仅复核方案不会修改候选，`review_existing` 允许空的 `changes`，但仍必须提供复核动作和验证条件；修复与来源编辑方案必须列出至少一项修改。不能为满足结构校验要求 AI 捏造修改，也不能因备选只复核方案没有修改项而拒收整包建议。

当前候选以 `candidateAuthority.versionId` 对应的 `candidateWindow` 为准，历史模型修复输出不代表已经应用。只复核方案还必须提供当前版本ID及涉及章节执行字段的准确引用；生成保存、只读投影与实际采用都检查来源。旧方案没有这类证据时保持可读但不可再采用，需重新获取。引用存在不等于争议已解决，语义准入仍属于后续评审。

当前候选完整明文前置，编码器不将其替换为跨版本引用。`candidateEvidencePaths` 只列可写章执行叶子的位置，引用仍须核对真实文本。历史修复输出投影保留义务及映射、理由、风险、复核目标和拒收诊断，明确省略整篇未验证执行稿；原始记录和来源指纹保持不变。精确去重的无损保证针对这一投影，不表示完整历史修复稿仍在付费输入中。

采用记录由服务器恢复请求的 repairKey 与 advice/option 标识共同确认，投影为 `applied`，不再暴露可采用选项。它仅说明方向已用于恢复，不代表审查通过或正文可写。未采用且来源变化仍为 `stale`；读状态不追加轮次、不重跑模型。切换简洁/专业界面仅改变 productionExperience，不能使创作来源失效；写作范围、正文、候选或用户意图变化仍需重验。

- `AdviceSource` 对全量来源、候选和用户意图计算指纹；`AdviceContext` 仅投影允许窗口、相邻只读章节和相关书级约束。摘要缺失必须显式表达，不用付费摘要补齐。大于本地容量上限的输入在调用模型前拒绝。
- 建议阅读权限与修改权限分开：通过 `planningPromises` facade 读取候选和基线各自的同卷路线视野（最多 24 条现有只读路线、同卷节奏板及覆盖说明）。已有第 5 至 7 章安排不能因不在修复窗口而从证据中消失；引用后续承接无需重复抄入本章合同。候选与基线分别标识，原文事实与计划仍保持区别，可写范围只取 `eligibleChapterIds`。
- `PlanningRepairAdviceService` 保存服务器持有的指导与执行方式；客户端只能选已有选项。`repair_then_review`先修改再复核，`review_existing`只重审不批准正文，`source_edit`不能直接恢复。旧方案缺方式时需重新获取；模型判定越界或修改硬约束的选项不可直接恢复。
- 选择沿用 `PlanningRepairRecoveryService` 的预约、来源重验和命令入队。只有修复方式追加一轮，仅复核不增加修复预算。执行方式、受影响章ID及指导一并持久化和校验；选项拥有稳定恢复标识，客户端换标识不会重复追加。确定的来源冲突可以撤销尚未执行的预约；结果未知时保留预约供明确恢复。
- 上下文同时提供本卷基线与候选的只读节奏板。只能引用已有承接，不能把窗口外安排的可见性误当成修改授权；候选内部节奏冲突需AI解释具体取舍，不输出系统无法执行的“直接开始正文”。
- 建议只发一次结构化请求；禁用传输重试、格式策略切换、备用模型和模型 JSON 修复。300 秒总期限同时传入 AbortSignal。应用重启后的未知结果不自动补跑。
- `AdviceContextEncoding` 在调用前按精确 JSON 相等去重长度至少 256 字符的重复原文/子树。首次定义保存在 `sources`，位置用声明的引用键指向定义；定义可引用更小子树但不会循环，键与输入原有字段避碰。它不总结、不删除、不改变权限；展开后必须与原投影 JSON 完全一致。容量检查使用编码后的实际字符串，仍严格限制 160000 个 JS 字符。唯一大内容无法无损缩小时在模型调用前失败，保留任务与轮次，不要求新手手工删减规划资料。
- 建议的完整字段、枚举、列表数量与长度由同一共享 schema 渲染到提示。说明列表最多 8 项，但恢复指导序列化仍限 4000 字符；窗口最多 3 章，不随说明容量放宽。执行合同禁止用静默裁数组或替换诊断值来通过校验。
- 建议必须声明执行方式：`repair_then_review` 先修改候选再复核，`review_existing` 只复核原候选，`source_edit` 需要先在来源工作区确认，不能直接执行。旧建议缺执行方式时只读展示并要求重新获取，不猜测其含义；任何建议都不能批准正文或跳过审查。
- 执行资格还要求 AI 明确声明阻塞覆盖：`blockerResolution.status=complete` 且无剩余阻塞；只复核同时必须是 `review_disagreement`。保留主要缺口的局部修饰、创作取舍降为待办、资料不明均不能直接执行。服务端只验证结构化声明，不用关键词判断剧情，也不把声明等同于审查通过。旧版本无阻塞核验声明时仍可读取，但须重新获取建议后才能采用；原有已授权恢复请求不受此展示规则替换。
- 显式恢复把执行方式、请求标识和允许章节范围持久化。协调器先应用已保存的付费修复响应，再执行新指导；新调用绑定轮次，应用候选成功后才清除一次性动作。只复核模式失败后暂停，不自动购买修复。窗口扩展必须来自结构化授权且属于未写可修复集合，邻章继承冻结字数预算。
- `AdviceFailure` 按结构化错误类型生成简短用户提示。确认完整收到但校验拒绝的内容只进入私有 `failureDiagnostics`，不投影到 GET，不成为可采用方案，也不触发第二次模型调用；来源变化时仍遵守 CAS 丢弃迟到保存。历史旧错误记录不在读取时改写。
- 单进程请求锁与数据库 CAS 防止并发提交；该本地部署没有跨进程租约。若部署多 worker，必须先把运行归属升级为持久化租约，不能把其他进程的在途请求判作重启遗留。
