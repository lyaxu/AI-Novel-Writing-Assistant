# 用户确认方向与规划承诺

本模块只读加载导演任务保存的 `seed.candidate`。指定任务时不回退到其他任务；旧书缺原型时明确未知，不能从后来生成的宏观规划、章节摘要或关键词猜测用户的原始选择。

同次候选中的 `hookStrategy`、`progressionLoop` 与 `endingDirection` 一起保留。旧候选可能对同一事件给出冲突章序；原型编号是待核对来源，不能单独充当唯一硬截止。语义审查须说明拆合后的回报是否完整且符合明确时限，不能以某个字段为由静默稀释。

方向是创作承诺，不是已发生事实。已写正文与原文证据优先决定连续性；承诺决定后续需要保留的关系、回报和卖点。合理改编可以改变表现动作和落点，但须保留相同叙事价值；延期须说明具体承接，不能用全书长期目标替代眼前的开篇回报，也不能要求长线承诺在当前章全部兑现。

调用方经 `index.ts` 加载并传入初始拆章、细纲与现有规划复核。`projectPlanningHorizon` 提供同卷最近24条已存路线与当前卷节奏板，显式说明遗漏；不按原型最后章号裁掉后续实际承接。不增加模型调用，也不扩大可修改窗口。复核使用有来源的 `promiseChecks`，缺口并入原有问题和修复指导；需要牺牲受保护方向时交回现有 AI 方案选择流程。

必审 ID 由已保存结构字段投影，包含卖点、人物路径、早期回报与原型当前及过去的开篇节点；未来节点完整保留供参考，不强求未规划未来章立即兑现。开篇来源不能改标为全书长线来绕过检查；延期引用实际只读开篇路线或候选，不能拿原型自身证明兑现。旧记录的检查字段可缺省，新模型输出必须完整覆盖预计 ID。

复核仍为既有单次调用，按必审承诺和历史问题数量分配 4000–16000 输出 tokens，要求最短充分引用以避免重复膨胀；这增加单次检查容量，不代表新增调用或允许自动追加轮次。Store 独立绑定已选候选来源与原文事实版本，方向变化不能复用旧检查。
