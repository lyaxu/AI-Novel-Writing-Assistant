# 已写正文证据

规划、场景合同和压缩事实都可能带有假设，因此不能替代已写正文证明人物拥有什么、知道什么、身体状态如何。本模块是章节规划与正文链共用的只读来源边界。

- `loadPlanningWrittenEvidence(novelId, targetChapterOrder)` 在同一只读事务读取当前章之前的正文和压缩事实，不读取未来正文、不调用模型。
- `buildPlanningWrittenEvidence` 最多提供最近三章、累计 24000 字符的完整正文。超限整章不纳入，不裁掉开头或结尾；覆盖信息列出排除章、遗漏数量、直接前章是否缺失。未覆盖不等于事实不存在。
- 每章有 chapterId、全书序号、原文 SHA256；sourceFingerprint 覆盖所有已写前章，较早章节修改也使来源失效。角色状态、规划文本、页面进度不冒充正文证据。
- 压缩条目放在 `secondary_not_proof` 层，仅供检索和对照，不作为“未提及的物品仍可用”的证明。
- 章节细化、修复、逐章审核和窗口审核共享来源。Store 在开始时验证请求快照，保存和提交仍受完整 source token/CAS 保护。
- 正常向后推进新增已写事实时，既有受审候选进入事实复核，不重生成初始合同、不增加或重置修复轮次；已写章节保护及真正的规划改动确认边界保持不变。
