# 卷规划持久化的执行归属

卷规划生成可以在 `onIntermediateDocument` 中直接保存完整的拆章结果。滚动路线服务拿到返回值后再检查取消状态，无法阻止此前的版本写入。因此取消保护必须进入保存事务，不能只放在外层调用前后。

`VolumeGenerationWriteGuard` 在模型调用前捕获工作流的执行轮次、开始时间及关联章节任务的执行者，在卷文档保存和章节实体化事务内复核。工作流取消、重试换轮次、章节任务取消、租约转移或过期，均拒绝迟到结果；已保存的正文和已审规划不受影响。事务结束前再次检查，避免将中途失去归属的结果提交。

- `NovelVolumeService.generateVolumes` 给有任务归属的生成安装写入保护，包含内部最终拆章文档回调。
- `ChapterRouteWindowService` 通过 `NovelVolumeService` 外观获取同一保护函数，并传入生成、卷更新和章节同步；这些连续操作共享调用开始时的执行归属。
- `VolumeChapterSyncService` 在版本和 Chapter 写入之前检查保护函数，避免取消后新增远期章节。
- 无任务标识的手动规划保持原有工作区行为；提供了任务标识但任务不存在或已终止时，禁止静默降级为手动写入。
- 该保护不批准规划内容、不刷新审查快照，也不重置规划修复预算。规划质量和已审合同一致性仍由 planningRepair 模块负责。

外部调用方使用 `NovelVolumeService` 外观；基础设施文件不作为跨模块的直接导入入口。保护函数是进程内事务钩子，不进入持久化任务请求或模型提示词。
