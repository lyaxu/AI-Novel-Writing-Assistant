# 人物身份与称呼

## 边界

本模块提供现有角色的精确姓名和持久别名索引。调用方通过 `index.ts` 访问；身份归属来自角色 ID 以及候选成员保存的 `appliedCharacterId`，不能用不同方案中相同的 `identityKey` 字符串跨方案猜测同人。

`characterIdentityRepository` 只读取同书且绑定到当前正式角色的候选成员；候选旧名和用户改名保留的别名作为已知称呼，正式角色当前姓名始终为显示与生成上下文的权威。未应用候选不授权匹配现有角色。

## 歧义与恢复

- 同一称呼关联多个 ID 时，索引不返回某个“最佳”匹配；不使用包含关系或相似名字归并。
- 自动人物确认遇到歧义保留待确认记录，人工从角色工作区选择身份。章后状态同步不得将这类歧义更新到任意角色。
- 新人物建立与候选绑定由 `dynamics/commands/confirmCharacterCandidateIdentity.ts` 在同一事务提交。失败不留下未绑定的新角色，重复确认复用原 ID。
- 阵容应用由 `characterPrep/application/applyCharacterCastIdentity.ts` 事务建立成员绑定；旧方案重应用不能改回角色资产姓名、覆盖用户资料或重建已有关系。
- 候选改名只更新规划元数据、别名和显式关系端点，不更改正文。正式档案改名与正文用名核对属于角色工作区。

身份索引是对结构化实体和明确绑定的确定性验证，不承担故事语义上的人物身份判断。相似摊主称呼等尚无可靠绑定的历史记录须另行核验，不能由本模块自动合并。
