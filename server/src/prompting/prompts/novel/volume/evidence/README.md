# 规划审查证据边界

`narrativeProgressionEvidence` 核验事件重复、认知重复、前章行动目标承接三项结构化判断。前情只接受更早章节的实际正文，当前候选引用必须精确；停滞必须关联实际阻塞与修复方向。合理回顾、安静的关系变化与有代价的失败可由 AI 判断为有效推进，程序不以题材词或动作数量替代判断。完整规则见 [跨章叙事推进审查](../../../../../../../docs/wiki/workflows/narrative-progression-review.md)。

模型负责判断问题是否解决、承诺是否保留以及延期是否存在真正承接。代码只核验来源、引用、覆盖范围和结构化决定，不用说明文字关键词猜测语义。

`planningStateReview` 负责声明逐项覆盖、原子命题比较、历史来源权限与统一修复方向。fresh wire 的状态到问题关联只写 `stateChecks.issueId`，反向 `claimIds` 由程序生成；`repairGuidance`、问题和推进检查的修复建议都从唯一决定投影。`established_in_plan` 是前提有效的计划，不是“计划提到过”；不能同时关联阻塞问题。旧历史问题仍按ID保留，分类与证据可根据本轮有效决定更新，避免锁死错误判断。来源过期由质量门返回候选修复需要，不能用重复审查调用掩盖。

`stateClaimBinding` 负责新规划合同的声明来源与场景归属投影。`resolveChapterStateClaims` 可由生成后处理和质量审查共同调用，将本次正文 ID 恢复为原始路径和原文；旧 ID、当前章/未来章或非正文来源不能冒充前史。`bindStateClaimContract` 只接受新 wire：本章声明位于场景 entry/action/after 数组，归属只表达一次。它生成兼容声明表、阶段引用、入口/离场及前提文本，聚合跨图错误供完整响应纠正，不按剧情词补边或选一个近似 ID。它不证明声明的语义成立：例如原文只说计划尝试，模型却声明已成功，来源可能有效而命题仍错误，必须由逐声明语义复核指出。

生成投影只执行一次。质量门的 `validatePlanningStateSources` 接收已持久化的 canonical 合同，必须调用 `validateCanonicalStateClaims`，不能再调用 fresh-wire binder：canonical 顶层声明表合法包含 `planned_scene`，而 wire 顶层只允许 prior context。canonical 校验核对正文来源、声明唯一性、归属场景和阶段、跨场景顺序与前提引用，不重写入口、离场或前提文本。结构和来源无效使用 `ContractRelationshipError`；意外实现异常直接上抛，不能把工程错误包装成需付费修改的小说规划问题。测试须覆盖实际 prompt 后处理 → scene-plan 序列化 → 质量门来源校验这一完整格式边界，包括无前文的首章。

声明 ID 在章内稳定，正文 evidenceId 绑定本次来源。修复保留仍正确的声明 ID，更新错误命题、时态或来源并同步场景引用；禁止把未来选择升级为已知事实，也不能把前章尚未做的事当作本章不得尝试的永久限制。来源变化时重新引用本次目录，不复用旧原文快照，不自动寻找近似替代。

`primaryProseCitationCatalog` 只负责显示正文的无损引用目录：按不超过240个UTF-16单元的连续段切分，保护代理对，逐字拼回必须等于原文。目录携带真实 `writtenEvidence.chapters[i].content` 来源路径；展示上下文中的回指占位文字不是证据，验证始终使用未变动的输入。压缩事实是辅助索引，不能把其中的概括署名为正文，也不允许程序将错误引用自动改到不同证据等级的来源。

质量审查 v18 调用目录时传入当前章序，为更早正文的片段附加 `evidenceId`；默认调用仍保留显示目录的原有结构。ID 以实际整章内容、章节身份、来源路径及片段偏移生成，不依赖声明的内容哈希。模型的 `progressionChecks.priorEvidence` 只允许 `{evidenceId}`，禁止附加手写 `quote` 或 `sourcePath`。`restorePrimaryProseCitations` 仅从同一输入的可选目录恢复精确原文，再进入已有严格校验；未知或过期 ID 不进行相似匹配、全文猜测或来源纠错。保存的领域报告继续使用 `{sourcePath,quote}`，其他证据字段和正文验收不切换协议。

`newIssueEvidence` 负责本轮新问题的证据准入。每个新阻塞必须有 `basis`，说明真实缺失或冲突、当前原文、已考虑的反证、对正文执行的具体影响，以及已有约束为什么仍不足。矛盾型问题至少引用两个不同真实叶字段；同一字段的路径别名不能充当两项要求。程序验证引用和判定一致性，不从剧情词语推断是否矛盾。历史问题继续由 `issueCheckProjection` 负责，旧记录不因缺少新字段而无法读取。

能力潜力、未来回报与本章必须执行的动作需由模型结合全部限制共同判断。已有明确限制时，单纯再补一句同义禁止可列入 `refinements`；若另一个场景确实要求执行被禁止的动作，仍属于真实冲突。可选润色不能进入阻塞问题或修复指令。只有润色不代表自动通过：本模块不把 repairable 改成 usable；AI 的显式准入决定、历史问题检查、承诺核验及窗口复核仍需全部满足。新阻塞与 usable、safeToSync 或 use_as_is 同时出现时拒收评审，不能选择性忽略冲突判定。

场景证据同时接受索引的扁平叶路径、保留 `causality` 层的场景 key 路径和真实 `sceneCards.scenes[index]` 路径。别名只由当前输入树逐叶建立，指向同一个真实叶值；不能任意删除路径片段或在全章搜索相似内容。错场景、错数组下标、伪造引用与路径冲突仍拒收。这样既防止捏造证据，也避免把模型正确引用的原始结构误报为缺失。

`issueCheckProjection` 在完整覆盖历史问题并验证全部引用后保留未解旧问题。模型本轮 `issues` 可只列新问题；遗漏重复的旧 ID 不应导致整份已收到的审查报错。旧问题使用原 ID、严重度、目标字段与修复方向，附本轮解释；新问题原样保留。不按近义标题合并，不因新增 ID 推断旧问题已解决。缺检查、伪造引用或 resolved 与仍列问题的矛盾仍拒收。

本轮模型自拟问题有数量上限；合成后的持久问题列表和历史检查不按同一上限裁剪，否则会丢失未解决事项。历史检查必须恰好覆盖输入列表，输出预算按检查数有界增加，仍是现有的一次调用。

延期的 `handoffStatus` 必须由模型明确给出 covered / partial / missing / conflicting。只有 covered 且有准确实际计划引用才能通过延期检查；有引用不等于引用覆盖承诺。非延期使用 not_needed。旧记录可缺此字段，但缺少明确承接判断不能自动当作延期已落实。真实期限、授权范围和用户硬约束不因原型拆章或后续节拍安排自动改变。

后续已有承接可直接引用上下文中的只读路线，不要求当前章合同再次抄写。读取窗口外来源与修改窗口外计划是不同权限；前者是判断现有安排必需的证据，后者仍需明确授权。候选自述“待确认”不应遮蔽实际已存在的来源，也不能据此把真正缺口直接判为已解决。
