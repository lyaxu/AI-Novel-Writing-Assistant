# 章节源页恢复交互

本模块只连接旧版章节执行页和章级生产检查点，不拥有另一条导演状态机。运行记录仍只读。

- `contracts.ts`：只读投影、结构化步骤标签、一次性新操作授权校验。
- `api.ts`：只读读取；失败时关闭写作入口，不猜测“没有执行”。
- `operationPermit.ts`：用户核对后的内存授权，限当前书/章节及上一操作；生成/修文点击消费一次，刷新页面不会自动保留授权。
- `ChapterProductionRecoveryPanel.tsx`：当前稿、执行快照和未完成流稿分开展示，可下载；恢复请求先刷新核验、使用同一操作号和服务端原参数。不会把部分稿自动覆盖到编辑器。

已有执行时，普通写作/修文按钮先引导核对；恢复按钮只在服务端 `canResume` 成立时出现。结果不明时不能普通恢复，用户须核对输出与调用记录，明确接受可能重复调用后授权下一次手动操作。授权前后检查快照变化，活动租约不允许新操作。归档和并发保护由后端最终判断。

带父任务的连续写作回原导演源工作区，章页不得绕过父任务的取消、预算和人工暂停。旧记录缺少完整参数时不能伪造恢复请求。

正文重写只发起写作，不预先清空正文；新稿的最终保存仍经后端版本检查。编辑器稳定实例、本地草稿和离开保护均沿用旧机制。本轮只验证类型和离线策略，交互与视觉验收由用户完成。
