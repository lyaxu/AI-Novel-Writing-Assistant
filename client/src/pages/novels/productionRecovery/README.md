# 章节源页恢复交互

本模块只连接旧版章节执行页和章级生产检查点，不拥有另一条导演状态机。运行记录仍只读。

- `contracts.ts`：只读投影、结构化步骤标签、一次性新操作授权校验。
- `api.ts`：只读读取；失败时关闭写作入口，不猜测“没有执行”。
- `refreshViews.ts`：生成、修文、恢复结束（包括失败）以及手动刷新保留进度时同步失效正文与资源提案缓存；失败也可能已经提交待核对提案，不能只在成功结束后刷新。
- `operationPermit.ts`：用户核对后的内存授权，限当前书/章节及上一操作；生成/修文点击消费一次，刷新页面不会自动保留授权。
- `ChapterProductionRecoveryPanel.tsx`：当前稿、执行快照和未完成流稿分开展示，可下载；恢复请求先刷新核验、使用同一操作号和服务端原参数。不会把部分稿自动覆盖到编辑器。
- `PipelineJobRecoveryPanel.tsx`：质量修复源页读取章级恢复投影绑定的原批量任务；仅服务端允许时同步预检并恢复原 job，沿用保存的范围、参数与预算。未知结果先回章页核对，带导演父任务仍回导演入口。

已有执行时，普通写作/修文按钮先引导核对；恢复按钮只在服务端 `canResume` 成立时出现。结果不明时不能普通恢复。服务端 `canAcknowledge` 成立时，用户核对输出与调用记录、接受可能重复调用后可保存同一执行的核对决定：只 POST acknowledge，不在客户端串接模型调用或父任务恢复；刷新后由用户另行选择恢复。已完成步骤、稿件、原参数和操作标识继续保留。

另起操作是独立选择，限无活动租约、非未完成父任务的章节。用户核对后授权下一次手动生成/修文，保留旧记录归档。两类授权前后都检查快照变化，归档和并发保护由后端最终判断。

带父任务的连续写作回原导演源工作区，章页不得绕过父任务的取消、预算和人工暂停。旧记录缺少完整参数时不能伪造恢复请求。

正文重写只发起写作，不预先清空正文；新稿的最终保存仍经后端版本检查。编辑器稳定实例、本地草稿和离开保护均沿用旧机制。本轮只验证类型和离线策略，交互与视觉验收由用户完成。
