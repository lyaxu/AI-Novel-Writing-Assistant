# 单一章节生产链的架构边界

状态：已批准的目标设计，尚未完成迁移；不能据本文断言运行实现已具备全部保证。

## 背景与决定

两版同题运行均暴露阻断，但修复后旧版首章得到目标用户认可。选择旧版创作能力作为基础，收敛生产执行、恢复与状态；不重建第三套界面，不用删质量检查换表面顺畅。

## 权威及依赖方向

创作规划提供版本化章节合同；章级生产服务消费合同，产出草稿、检查与择稿结果；最终保留正文驱动事实提交；导演只编排下一章，前端只投影状态。迁移要找到现有权威写入者，而不是追加一套相同职责的状态机。

- 计划是将来打算发生的事，事实是保留正文确实发生的事，不能互相冒充。
- 运行步骤状态、产物保存状态、质量结论、事实同步状态分开建模；一个环节完成不代表全链完成。
- 恢复依据持久化产物和输入版本，只补未完成步骤。任务所有权与版本校验阻止重复执行和覆盖人工改稿。
- 外部 API 不确定是否完成时保留不确定状态，不能承诺请求/收费 exactly-once。
- 无效审查是检查过程的问题，不得转换成无证据的剧情修改。局部债务遵循任务策略；严重结构问题仍沿用显式暂停与恢复。
- 近期联合规划与当前合同冻结分离：不冻结整本细纲，也不每写一章从零推翻卷战略。

## 迁移纪律

旧版已在审查前保存初稿，也已有近期规划，不把已有能力当成空白重写。每次只迁移一个完整职责，兼容旧入口但保持单一写入权威；验证故障恢复后再切换默认入口。所有创作提示词仍经 Prompt Registry。

章节编辑防丢稿、写前规划复核、预算持久化、原稿保留、字数限制与源工作区恢复必须保留。题材标签及节奏曲线不能代替剧情理解和人工阅读。
