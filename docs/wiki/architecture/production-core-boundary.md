# 单一章节生产链的架构边界

实施与验证状态见 [CURRENT](../../handoffs/CURRENT.md)。本文记录稳定边界；离线验证、真实源页交互与连续写作验收分别登记，不能互相替代。

## 背景与决定

两版同题运行均暴露阻断，但修复后旧版首章得到目标用户认可。选择旧版创作能力作为基础，收敛生产执行、恢复与状态；不重建第三套界面，不用删质量检查换表面顺畅。

## 权威及依赖方向

创作规划提供版本化章节合同；章级生产服务消费合同，产出草稿、检查与择稿结果；最终保留正文驱动事实提交；导演只编排下一章，前端只投影状态。迁移要找到现有权威写入者，而不是追加一套相同职责的状态机。

- 计划是将来打算发生的事，事实是保留正文确实发生的事，不能互相冒充。
- 运行步骤状态、产物保存状态、质量结论、事实同步状态分开建模；一个环节完成不代表全链完成。
- 恢复依据持久化产物和输入版本，只补未完成步骤。任务所有权与版本校验阻止重复执行和覆盖人工改稿。
- 外部 API 不确定是否完成时保留不确定状态，不能承诺请求/收费 exactly-once。
- 无效审查是检查过程的问题，不得转换成无证据的剧情修改。局部债务遵循任务策略；严重结构问题仍沿用显式暂停与恢复。
- 近期联合规划与当前合同冻结分离：不冻结整本细纲，也不每写一章从零推翻卷战略。

## 迁移纪律

旧版已在审查前保存初稿，也已有近期规划，不把已有能力当成空白重写。每次只迁移一个完整职责，兼容旧入口但保持单一写入权威；验证故障恢复后再切换默认入口。所有创作提示词仍经 Prompt Registry。

章节编辑防丢稿、写前规划复核、预算持久化、原稿保留、字数限制与源工作区恢复必须保留。题材标签及节奏曲线不能代替剧情理解和人工阅读。

实施阶段与验收见[核心重构方案](../../plans/2026-10-11-production-core-refactor.md)。

## 持久执行与人工改稿

执行记录复用现有检查点表，固定到章的活动槽位承担互斥；任务表继续承担全局工作流状态。先持久化完整 writer 输出，再由唯一生命周期保存入口写入正文，避免把数据库保存失败当作再次购买模型输出的理由。部分输出只保留在执行记录，不能作为完整正文送审。

正文、标题、任务单、场景卡、章节预期和字数目标共同构成本章版本。人工编辑可以发生，但旧执行不得覆盖编辑后的正文或终态。未知模型输出不会因租约过期变成重新调用许可；显式新操作须归档旧证据，并由源页承接。运行记录及恢复 GET 均不改变状态。

步骤复用与内容审查缓存用途不同：前者回放同一操作已经完成的步骤，后者依据精确有效输入复用审查。两者不能用“正文相同”代替模型、上下文及执行身份核对。

模块职责、源接口及尚未覆盖的跨资产事务边界见 [reliability README](../../../server/src/services/novel/production/reliability/README.md)，离线证据见[阶段 2 报告](../../evals/2026-10-11-production-core-stage2.md)。
## 源页恢复与操作身份

源工作区是恢复操作面，运行记录只读。恢复请求只提交操作ID，参数保存在服务端并按原入口复用，避免刷新页面后用默认模型/写法冒充原执行。未知调用、输入变化与历史缺参不能由普通重试隐式放行；新操作只来自用户核对后的明确选择。父级范围任务仍拥有取消、重试预算和人工暂停，章级恢复不接管该权威。

未知结果须先保存明确的用户核对决定，保留原操作、请求、完成产物及部分稿；核对决定本身不调用模型，不解除父级人工暂停。之后用户另行恢复原任务，仅执行未完成步骤。范围执行的章操作身份由 jobId 与 chapterId 固定，不以新随机标识躲过旧暂停。历史随机身份记录不推断归属、不自动迁移。

## 一份有效合同及审查有效性

Chapter 中已审核任务单、场景卡、职责与字数目标是执行合同；StoryPlan 是其细化视图，必须具备相同合同指纹。允许保留角色、回报与转折等有用细节，但过期计划不能反向覆盖已审任务。已有正文的审查/恢复不重新做 JIT 或补生成计划，计划等待期间发生人工改稿/改合同必须拒绝迟到提交。

写前门禁适用于所有无正文入口，仍沿用同卷当前及后两章、两轮持久预算。窗口预备范围不扩大自动修正权限。合同准备和细化计划分步持久，恢复不能重做已完成门禁。

审查中的调用失败、缺查项、引文校验失败是“审查未完成”，不是正文已通过，也不是有证据的剧情问题。禁止由异常构造接受结果或把无效意见送去修文。已有结构化、有证据的局部问题仍遵循 completion-first / quality-first；显式 stop_for_replan 优先于 local_window 范围，不能因范围较小自动改计划。生产会话中的不确定传输失败不能被底层重试/备用模型隐藏；额度耗尽仍终止自动调用。

## 最终保留稿的实际状态

正文先保存，之后审查报告、时间线、实际资产分别以可恢复步骤提交。每一步的本地数据和步骤完成标记在同一章级租约/正文版本事务中落盘；外部提取先缓存，绝不在数据库事务内调用模型。8 类实际资产消费者共享一笔本地事务，必要伏笔对账及提案核对完成后才写总边界。禁止把计划义务当作已发生事实。

带质量债的保留稿也要提交真实发生的事件。质量债来源本身不强迫低风险事实人工确认；原有高风险和无效提案检查继续保留。提案先落盘，再暂停边界，用户可在原状态工作区确认有效提案或明确忽略；无效抽取不能直接确认。自动拒绝/归档不冒充人工核对。

下一章在缓存准备之前读取前章精确正文 hash 及其当前 operationId 的完成边界，旧稿边界或其他操作的边界不能放行。旧后台、手动资产同步入口不得双写受生产日志管理的章节。正文换版产生的旧自动事实/时间线保留为 superseded；上下文、导出及 RAG 读取排除失效事实，不能只依赖异步索引清理。
