# 跨章叙事推进审查

## 背景与边界

细腻是表达方式，推进是故事状态的变化。只检查本章内部的起承转合，容易把上一章完成的买卖、问路、检查物品再次当成新事件，也可能把人物已知信息重新写成发现。章末再次决定执行前章定下的行动，不等于完成了承接。

本规则适用于章节细化、写前语义审查、正文生成、正文验收和修复。AI 根据正文事实、题材与章节职责判断；程序只校验结构、证据和决定的一致性，不按关键词、动作数量、打斗或胜利次数评分。

## 三项判断

1. **事件重复**：重演已有事件时，是否产生不同结果、代价、关系或信息？回忆、仪式、伏笔、喜剧复现可以成立，但需要说明本次作用。
2. **认知重复**：区分读者知道、人物知道和人物相信。补充证据、修正误解、加深误判、从知道到承认均可能推进；同一角色无理由再次发现已确认的信息属于停滞。
3. **前章目标承接**：前章明确决定的行动是否真正尝试并形成结果？受阻、失败、目标被新事件改变也可成立，但应有具体原因和后果，不能只用再次出发延后。

推进不要求每章完成大目标。安静的关系变化、信念动摇、解开一个小疑点、承担一个新条件也可构成结果。细节应服务这些变化，不机械压缩情绪或强制所有题材套用快节奏。

## 证据与兼容

写前审查引用当前候选的准确叶字段，并以更早已写正文作为前情证据；后续计划和概括不能冒充已发生事实。三项判断必须完整且各出现一次。停滞判断必须关联阻塞问题和具体修复方向，不允许一边判停滞、一边无条件准入。

正文验收引用当前正文与带章 ID 的前章正文证据，保留前状态、实际变化和新后果。引用失真或前情不足应标记证据不足，不能靠模型自述捏造过去事件。

历史记录允许缺少新增字段，以保留阅读兼容；新调用必须输出完整判断。验收缓存必须匹配当前请求身份，包括 Prompt 版本和实际上下文，不能仅因正文哈希相同而复用旧规则报告。

## 修复与运行策略

### 自动入口的事实新鲜度

预先审过下一章计划，并不代表该计划在前章落笔后仍可执行。所有非 manual 的自动执行模式，在写手启动前必须进入统一章节合同准入；中央 Store 使用已写正文指纹判断是否复核，保留同任务的修复轮次、候选及已写章节保护。只有全书自动模式可以额外准备后续路线，复核不能顺带扩大用户选择的写作范围。

典型失败是前章实际提前完成交付，而下一章仍被要求首次交付。即使写手拿到了完整前文，同时输入这两份互相冲突的合同也不能形成可靠承接。应先用最新事实核验未写章节职责，不靠写手临场选边，也不回滚已写正文。

### 问题保留与补丁回执

验收合并动作、推进、场景和模型问题后必须完整保存与传递，不按数组前五项、前四条等位置截断。否则新增的普通证据缺口会挤掉严重连续性问题。补丁执行数量可以限额，问题记录和未处理义务不能因此消失。

每次局部补丁请求提供稳定问题编号，返回逐项处理回执：本轮有补丁、暂留、指控不受证据支持或规划冲突。已打补丁的回执必须双向引用实际补丁；未处理项必须说明原因。回执随候选选择或质量债保存，保留原始问题证据。模型声明已处理不等于验收通过，候选仍须复审及安全选择；旧保存计划兼容读取，新生成计划不可省略回执。

回执追加到章节修复历史，后续通过审查或普通状态滚动不能删除。手动入口区分候选已准备与应用失败，自动流水线区分候选被选中与保留原稿；这些状态都不等于文学验收通过。结构非法的模型响应不冒充有效补丁计划，仍按失败路径保留原问题及调用日志。

引文来源纠错耗尽后，保存原始问题、原建议及验证失败原因；未核实问题排除出可执行补丁清单，无法逐项关联的指令和义务暂存待复核，不能被通用润色兜底重新激活。该恢复路径仍须通过完整场景覆盖检查。手动选择已有审计问题也遵循同一保护；用户直接输入修改要求及旧独立审计入口不推定拥有新来源证据。

前章原文、当前正文与审查指控是三个不同来源。新问题引用须标注实际章节，不能用前章事件证明当前章发生同一事件。AI 分别判断是否重复与是否有新后果，程序仅核对结构化结论一致性及引文来源，不解析情节关键词判罚。认识内容、位置、方法等不同命题不能混为一个“知道/不知道”。

生成与修复共同要求保留有效细腻描写，把重复篇幅用于现场交锋、选择和结果。错误章节职责需要先调整规划，不能要求局部正文补丁偷改整章合同。已兑现事件应停止作为新义务，尚未兑现的承诺仍须保留其功能与合理承接。

本规则不新增全局停止类型。写前仍遵循规划准入和授权范围；已写正文中的停滞进入现有局部修复或质量债务机制。完成优先与质量优先策略仍由统一问题决策决定，不因新增审查字段偷偷改变自动导演的恢复行为。
