# 故事原型与样章试读

## Background

连续性和流程完成度是底线，不等于阅读吸引力。把单件工作切成数章、反复描述同一代价或只增加疑问而不给回报，会让完整的章节规划产生平淡正文。目标是低成本筛选值得作者加工、继续展开的故事，而非证明 AI 填齐了所有字段。

## Decision

- 模糊灵感先形成两套故事原型，比较人物愿望、阻力、两难选择、独特推进机制、早期回报与无聊风险。
- 原型附带连续第1章起的3–5章事件链；后一章应承接前章选择的后果，不是重复另一个同类小任务。安静的人物关系变化也可有效，不强制章章打斗或反转。
- `DirectorCandidate.storyPrototype` 是旧数据可选字段；新候选与定向修改输出必须完整包含它。结构校验只检查字段和连续章序，不以关键词或分数冒充文学判断。
- 原型通过 `normalizeCandidate`、`buildStoryInput` 和书级上下文传入宏观规划、书级合约及后续卷章安排，不能只显示在候选卡上。定向改候选时同步更新事件链，旧候选缺失时补齐。
- 卷节奏板和章节清单保留选定原型的选择、后果和早期回报；正文任务约束结果与因果，而不规定逐项扩写操作。锁住硬事实、必达义务、必要先后关系、章节预算及后章边界，允许作者模型决定切入点和详略。

## Current Rule

开写交接提供 `sample3 / sample5 / book`。UI 默认前三章；旧 API 不传范围时保持全书兼容。样章是既有导演 Runtime 中的显式 `chapter_range`，仍使用自动审校、修复、JIT 规划和断点恢复，不另建生产引擎、不改数据库表。新范围不会改全书目标章数和单章字数。

样章完成后任务结束，后续章节保持未写，书架显示等待试读而非全书完成。普通刷新、后台恢复与创作界面切换不能扩大范围。读后明确续写使用完整工作台的 AI 接管入口；它是新的用户授权，不由第二读者自动决定。`productionScope` 记录首次选择，后续真实范围以执行计划为准。

第二读者按需读取已写章节，判断是否值得展开、哪里在重复、行动是否改变局面、旧问题是否得到回报。报告只是作者参考，不写入导演阻塞状态、不自动重写、不授予全书生产权限。没有新增一项必须通过的吸引力评分。

### 使用顺序

1. 新建自动导演，输入想法。比较两套候选的具体冲突与开篇事件链；不满意就带修正意见生成下一批，或定向修改候选。
2. 选定方向，完成开写准备。在“本次写作范围”选择前3章（默认）或前5章，再选创作界面。
3. 样章完成后读正文；在书架或完整工作台的“第二读者”中选已完成范围，点“评估是否值得展开”。不要选还没有正文的章节。
4. 有兴趣再切换专业模式，从 AI 接管明确扩写；没有兴趣可以换原型，不必先等80章全部写完。

## Failure Modes

- 原型字段齐全但仍模板化：不能宣称吸引力已通过。读实际候选和样章；检查行动是否由人物利益驱动、解围是否依赖临时新规则、后章是否抹掉前章后果。
- 界面切换重设章节范围：只能局部更新体验字段，不得重建 Seed 的执行配置；条件更新冲突时提示重试，不能覆盖并发进度。
- 样章完成后仍自动续写：检查 `autoExecutionPlan` 是否被 full-book 默认覆盖，以及完成/重启分支是否按授权范围判断。
- 曲线低就不给读者答案：冲突/揭示分数只是辅助，不能覆盖本章已承诺的回报。不自动缩放或改写已有小说的旧分数。
- 自定义高级写作模板覆盖出厂规则：应在提示词预览核对实际消息，不得为上线此能力静默覆盖用户模板。

## Upgrade Invariants

1. 新原型的结构保留到下游，旧候选仍可读取。
2. 样章范围持久化且重启不扩大；显式续写之后切换界面也不缩回原样章范围。
3. 第二读者保持按需、只读建议；既有质量检查不关闭，规划修正两轮预算和事务提交不变。
4. 章节防丢稿、连续性约束、字数上限和已有正文保护不变。
5. Prompt Registry 的加载键与资产实际版本一致，不用登记旧版本来假装兼容。

## Verification

回归覆盖 `storyPrototype.test.js`、`simpleCreationMode.test.js`、`novelDirectorAutoExecutionRuntime.test.js`；联合运行规划修正、提示词、第二读者、字数控制和章节预览测试。UI 需检查默认3章、5章切换、事件链展开与第二读者弹窗。模拟范围完成测试只证明运行边界，不能代替连续样章的文学质量验收。
