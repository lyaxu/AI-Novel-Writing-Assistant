# 写前规划自动修正与复核

## 决策与边界

规划器产生的任务安排不合格时，应由工具消化检查意见，而不是把创作意见作为接口异常交给作者。修正不能通过关闭审查、增加字数或丢弃伏笔获得表面成功。

本闭环只处理写前的任务单与场景合同，同时服务拆章准备和全书自动模式的即时规划。正文审校的质量债务政策和独立第二读者不变。

- 使用任务显式选择的模型，当前本机为 DeepSeek Flash；不自动切换到 Opus。
- 单章问题在单章内修正；结构化评估要求窗口重排时，范围最多为当前章及同卷后两章。
- 有正文、正在执行或受保护的章节不允许改动，遇到边界收缩窗口，不跨卷扩大。
- 书级设定、人物关键走向、卷目标、章节数量和各章字数预算不变。
- 未单独填写章长的章节继承小说默认章长（旧数据未配置时使用现有导演默认值 2800），并在修复快照中冻结；不能由修复模型扩大预算。
- 每个卡点默认两轮，每轮包括修正和复核；普通继续、刷新、重启都不能重置预算。

## 执行与持久化

`PlanningRepairCoordinator` 负责生成、检查、修正和整体复核；`PlanningRepairStore` 负责快照、候选、并发校验及事务提交。两者位于 `server/src/services/novel/volume/planningRepair`。

初次生成先保存候选，随后检查。局部修正和窗口重排均使用完整原始评估、当前候选、书级约束及窗口两端只读上下文。返回的义务去向记录必须与实际章节安排一致。

逐章结构和语义检查通过之后，还要整体检查职责遗漏、重复、字数负载、伏笔去向、人物状态及章节衔接。写前提交要求明确的 `usable` 和 `safeToSync`，不能只检查旧的全书模式 `canEnterExecution` 放行标志。

候选存入 `VolumePlanVersion` 草稿，任务 `seedPayloadJson.planningRepair` 保存版本化轮次、阶段、候选引用、检查结论、指导意见和调用中的标记；原始快照单独保存在 `planningRepairSnapshot`。无数据库表迁移。

调用前写入阶段及轮次，调用成功后立即保存结果。响应丢失不能假装尚未调用；恢复时显示不确定状态，请作者确认再继续。网络错误保留技术错误类别，不伪装成质量不通过。

全部检查通过后，在事务内激活候选版本、同步受影响的章节合同并失效旧章节计划。提交前重查数据指纹、任务所有权、正文和保护状态。只读范围不能改动，任何并发冲突都不能覆盖较新内容。上层调用识别已提交结果，不再二次覆盖写入。

导演心跳和进度轮询允许独立更新，但不能覆盖规划修正状态、快照和人工授权记录。普通任务写入在事务内读取最新修正记录后合并；待确认或已取消的修正不能被迟到的进度写入重新启动。模型、指导意见或任务所有权的并发变化仍阻止提交。

## 人工介入

两轮不通过、需要突破修改范围或改变受保护方向时，进入 `waiting_approval`，使用 `step_review_required` 和 `pendingManualRecovery`，不跳到正文重规划分支。

在小说的「节奏 / 拆章」源工作区查看规划修复状态、意见及轮次，补充修复方向并明确追加一轮，或保持暂停。重试请求有幂等标识；重发请求不能多领取预算。普通继续与跳过审校不能绕过此确认。

运行记录页只展示状态和返回源工作区的入口。修复成功也不改变原任务的运行模式：推进到可开写仍停在可开写边界，不擅自启动全书正文。

## 验证与维护

回归测试包括本机第3章职责过载记录、纯候选约束、两轮上限、技术错误、丢失响应、数据并发、事务回滚、恢复授权和接口幂等。真实验收只调用指定章节的规划闭环，不启动导演后台调度器。

后续升级必须保留四项行为：针对检查意见修正、修后严格复核、整体事务提交、持久化的调用预算。不要恢复全书模式在写前绕过语义检查的旧逻辑。
