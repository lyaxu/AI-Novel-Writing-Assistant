# 断线续作与书内创作 agent：待设计想法

来源：2026-10-11用户在《外卖小哥的茅山账本》首章验收时提出。状态：讨论与记录，未批准实施，不改变当前固定版本，不启动模型任务。

## 一、断网、合盖、休眠与重启后的续作

用户期待恢复联网/供电/开盖后接续工作、不丢稿；需要覆盖操作系统重启，不只网页刷新。

初步方向是复用已有章节journal与父任务状态，按完成步骤接续。已有能力包括完整稿/部分流稿持久化、原任务操作标识、正文合同指纹、保存与完成标记事务、未知结果暂停和显式恢复；这些离线能力不等于合盖/断电真实验收已通过。本次发现的failed任务恢复接缝必须先收口。

必须分清场景：

- 仅网页断开、后台仍运行：重连先读取实际任务和落盘结果，不重复启动。
- 网络断开：本地已保存步骤可复用；远端模型可能仍运行或计费，不能把请求超时当成没有执行。
- 合盖睡眠/休眠：进程可能冻结后恢复，网络连接和租约可能失效；先校验所有权、任务是否结束及未知调用，不让旧回调与新请求抢写。
- 电脑重启/掉电：靠持久日志与一致性事务恢复，不能依赖内存、前端页面或旧PID；最后尚未落盘的流片段不能承诺百分百找回。

理想交互是打开书就看到“已保存到哪里 / 哪一步未完成 / 能否安全继续”。确定性的本地保存或资产事务可以幂等回放；有供应商查询能力时优先核对已知请求。未知外部结果、输出额度、预算、质量策略人工暂停仍需明确决定。自动恢复模式应以后由用户按任务授权，不能把本设想视为恢复历史导演许可。

未来验收矩阵：写作流中断、完整输出后保存前、保存后审查前、审查返回后落盘前、实际状态事务中、已完成但浏览器未收到响应；分别验证断网、休眠、杀进程和重启，检查保留字节、重复调用/费用、原operationId、取消竞争、人工编辑及前后章边界。先离线故障注入，再在独立测试库中做真实设备验证，避免拿认可正文冒险。

## 二、与本书紧密联动的创作 agent

用户希望在写书时随时讨论情节、脑洞、人物、伏笔，并协助落实调整；可以内嵌，也可以专用联动窗口。重点是足够且正确的本书上下文，不是另做第三版GUI或通用闲聊器。

初步可行方向：现有书工作区内的“创作伙伴”，先做只读讨论和可审阅建议，再逐步开放受控修改。上下文由书级方向、用户认可写法、角色/世界规则、已写正文、当前任务合同、实际状态、伏笔、待核对提案和近期讨论共同组成。必须分清“已经写成的事实 / 未来计划 / 提议但未采纳 / 已否决”，每次回答关联具体章节与来源，不能把全书粗摘要当成完整记忆。

动作分级：讨论不改书；建议生成受影响范围与差异预览；用户确认后通过现有业务接口应用到目标章节/计划，保留版本与撤销。应用前比较正文版本与正在运行的任务，必要时在安全边界暂停；不能绕过写前门禁、审查、预算、Prompt Registry或防覆盖机制。

最小可验证场景：询问一条伏笔在哪里铺设、提出三种回收方案、说明各方案影响哪些未写章节、确认后只调整明确范围，并由原导演继续执行。后续再扩展人物弧光、节奏讨论和跨章调整。是否与外部agent窗口联动、如何持久化讨论、模型/费用策略和主动建议频率留待专项设计。

## 顺序

先完成当前单章审查及恢复闭环，再完成连续十章真实验收；随后设计系统中断续作，书内创作agent另立较大的设计阶段。本文不安排后台执行、周期任务或自动模型调用。
