# 书级构思泛化评测说明

## 状态与用途

配套文件：[book-foundation-cases.v1.json](book-foundation-cases.v1.json)。当前为人工编写的 **7 组、14 个候选构思**，尚未调用真实模型评分或生成，质量提升、调用耗时、token 消耗及费用均待测。结构检查通过只能说明材料可读取，不能写作模型评测通过。

本材料承接外卖样本暴露的世界边界、人物功能单一和整书落点问题，测试的是跨题材判断，不用于修复或续写该样本。既有观察见 [外卖前三章审读](observations/2026-09-28-delivery-opening.md)。案例不进入正常写书上下文，不作为运行时路由或关键词判定规则，也不替代 Prompt Registry 中的产品合同。

## 评价边界

书级“大底”是作者知道主要矛盾最后如何落定、人物做出什么选择以及后果如何表达作品意图。它可以是文明抉择，也可以是开店、守约、赢得信任；不强制牺牲、宏大阴谋、系统真相或道德说教。轻松赚钱、快爽打脸和升级均可成立，检查的是它们是否持续改变处境与关系。

世界边界区分叙事发生地、主角来源、叙述比喻、实体道具和人物知识。跨时代交替合法；读者看见古代线不意味着现代主角知道古代秘密。作者已规划的未来信息也不是当前人物已获知的信息。虚构异能或民俗规则评价内部一致性，不外推为现实科学事实。

关键配角应有自己的目标和行动，并至少在一个关键节点改变主线。群演可以只负责环境、社会反应或场面节奏，不要求每个路人背负伏笔。情绪组合按题材和经历需要选择，不要求每章齐备讽刺、荒诞、搞笑、热血、泪目，也不要求每章反转或胜利。

## 维度与评分锚点

每维 0–2 分，另记原文证据与置信度；总分只便于对照，不等于小说文学评分。材料未提供某项所需信息时记“证据不足”，不要把未描述当已违背。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| ending_choice | 落点违背请求或用口号代替主矛盾收束 | 有结局方向，选择与前因联系薄 | 关键选择、后果与起点承诺相连，表达有具体载体 |
| world_boundary | 已建立规则被关键情节无依据突破 | 主要规则可用，但来源或信息边界仍有空缺 | 时空、能力、道具和人物知识可追溯，合法变化有依据 |
| character_agency | 关键角色仅供嘲笑、围观或工具性让路 | 有独立目标但对主线作用弱 | 独立目标产生行动，确实改变方案、代价或关系 |
| emotional_causality | 情绪靠标签、突发煽情或固定轮播 | 局部回报成立，跨阶段积累薄 | 情绪来自已发生事件及关系变化，铺垫有回报 |
| progression_variety | 主线仅换壳重复或临时外挂清障 | 有变化但阶段之间因果弱 | 各阶段改变目标、认知、关系或约束，保留题材乐趣 |

`answerKey` 指出主要差异及可核查证据，不要求正例所有维度必得满分，也不意味着反例所有部分都差。多数对照故意保留相同优点，以免评审只按华丽用词或篇幅判断。部分正反例仍存在长度差异，实跑报告应承认这一混杂因素，不把一次偏好当精确效果估计。

## 离线材料核验

无需模型调用即可确认：JSON 可解析、案例 ID 唯一、七类题材齐全、每组恰好两个不同候选、答案指向实际候选、判据能在文本定位。代码只能校验这些结构；语义优劣由盲评和人工阅读判断，不能用关键词命中代替。

当前文件与原有 `cases.v1.json` 的用途、字段不同；不要把它直接交给现有脚本并宣称兼容。接入执行器之前应明确输入转换、输出记录和答案隔离。

## 后续盲评办法

1. 固定案例版本、模型版本、参数、Prompt 版本和被评估代码提交，保存输入与输出哈希。保留请求与两段构思，移除 `answerKey`、文件名提示、正反标签和本说明中的判据。每组随机交换展示顺序，使用不透露答案的新展示 ID，映射只由执行者保存。
2. 评审先分别给出维度判断、原文证据、证据不足项，再选择偏好或平局；不提供期待结论。将准确识别主要缺陷和保留合法风格分别统计，不能只报选中预期答案的比例。
3. 收集人类独立阅读或与生成器分离的模型判断，记录不同意见。至少检查日常快爽、传统武侠和双时线是否被强行宏大化、悲壮化，或把合法跨时空误判成穿帮。
4. 用同样输入和预算对比代码优化前后的真实构思输出，隐藏版本标签后评审。开发集已被实现者阅读，不能称为留出集；后续另写未经调试的同题材新故事和混合题材留出集，避免仅学会这些七个答案。
5. 首轮只测书级构思，再用选出的新样本检查卷级展开是否继承终局、世界限制与角色动机，最后检查正文是否兑现。书级识别通过不证明卷章传递、全书回收或文学质量通过。

## 结果记录与成本边界

每次记录运行 ID、UTC 时间、提交、数据版本、展示顺序映射、模型与参数、每项原始输出、各维分数/证据、偏好/平局、人工异议、失败类型、输入输出 token、耗时及实际费用。未提供的费用记未知，不以估算冒充账单。重试次数、重试原因和额外费用单列，格式失败、网络失败与语义不合格分别计数。

当前未安排付费调用，未设置自动重试，未启动任何样本书，也没有完成盲评成绩。执行模型评测前先确定模型、次数和预算；不能因材料已落盘就自动开始生成。正式接受标准应同时包含请求遵循、主要缺陷识别、合法风格误伤率和留出表现，不能只看总分上涨。
