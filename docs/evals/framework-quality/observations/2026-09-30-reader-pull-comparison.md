# 局部禁令与持续延期：通用修复及短样本对照

## 用户目标

保留细腻文风，减少原地重复，让小人物的行动带来实际结果；不把苦练、代价或长期铺垫当作所有金手指的前提。先修通用约束与回报路径，再比较同剧情的表达改写和推进重构。

## 原样本与根因

已读取《外卖箱通金庸》第5—8章全文及生成上下文。约1.56万字符的四章存在多次待签收、担忧箱子、反复试探等推进稀释；部分相邻章退场、报酬描述也不一致。细腻本身不是延迟交付的理由。

代码存在两条确定性放大路径：场景 `forbiddenExpansion` 被合并到全章 `doNotCross`；`pending_payoff` / `overdue` 被机械映射成 `pressure`。此外，账本含秘密文字时，关键词匹配会把整个回报改成 `forbid`，即使当前合同允许得到奖励而只禁止揭示来源。

## 本轮实现

保留场景标识的局部限制贯穿写作、审查、修复及预览。章级规划输出结构化回报决定，校验当前合同引文及未来承接引文，随计划保存并校验合同/前文新鲜度。执行端保留 AI 的范围决定，独立携带保护信息；不再以逾期或文字重合替 AI 作出禁止/施压判断。

金手指授权规则统一进入相关写作、规划、验收和修复 Prompt；同时获得并使用能力的原文允许同句生效。新能力仍需符合本书授权和已确认限制，不能凭题材标签随意发明技能。

旧的未写计划缺决策或来源已变时重新规划；已有正文不因此自动重写。需要重排时返回明确规划错误，未新增完整自动重排与专属恢复界面。

## 短样本方法与结果

实验文件位于 `.codex-run/reader-pull-comparison/`，未写回正式数据库。使用 DeepSeek `deepseek-v4-flash`、writer v12、温度0.7，同一第四章末起点，目标1200—1500中文字符。

- A：保留旧事件结果，仅改善表达。首稿新增箱子标记人物功能等越界，经修订消除。阅读稿约1353汉字，仍反复待签收，缺少实质回报。
- B：允许改变冲突解法与交付落点。首次调用耗尽4500 token输出预算，无正文；增至12000后生成，但把喝水和欠免费跑腿当作关系成果，不合格。
- B再次修订获得部分现金，却延期另一半并新增系统记录线索功能，仍不合格。
- B最后定点修订完成交付、当场结清酬金、争取免例钱，并留下新的交易要求。模型原稿约1219汉字。供阅读版仅人工纠正两处“药价/药款”为“跑腿酬金”，原稿另存。

B具备更明确的行动结果，但台词博弈与章末吸引力仍需用户判断。它接受了更多人工明确反馈，不是等调用次数实验，不证明自动导演一次成稿就能达到同等效果。失败样本、模型请求、响应及用量元数据均保留，不隐去筛选过程。

## 验证

- 共享库与服务端 TypeScript 编译成功，客户端 `tsc --noEmit` 成功。早先曾遇到 dist 写入权限问题，最终本轮完整服务编译成功。
- 最终14个定向测试文件：141项，139通过、2原有跳过、0失败，使用 Node24 与 `SQLITE_ENABLE_WAL=false`。覆盖场景范围、部分/即时兑现、延期证据、陈旧决定、已写章保护、能力获得顺序及Prompt注册版本。
- 单独的治理测试发现旧 `ComicFactService.ts` 两处未登记内联提示词。该源文件与治理测试对照HEAD无改动，保留为既有检查缺口，不能宣称全套测试通过。
- 真实 DeepSeek 正式章规划 Prompt v3匿名案例：已确认信标可赠予一次听风能力，来源保密，当前章救人。返回 `payoff`，安排立即获得与使用，没有额外苦练、付费或献祭；本地真实合同引文校验通过。其后仅补强Prompt中“获得奖励与揭示来源分开判断”的说明，该文字修订未再次付费实测，最终编译及离线测试已覆盖。
- SQLite只读对比原书9条章节记录，全部所存字段（除时间戳格式）无变化。没有覆盖正文、保存新计划或生成第9章。

## 后续验收

先让用户读A/B，确认推进方向与阅读感受。若B方向被接受，再使用同题材独立新书验收前三章，明确要求一个配送闭环和可见回报；原书保留。工程回归、付费匿名规划、短篇阅读对照、真实自动导演全链是四种不同证据，不能互相替代。
